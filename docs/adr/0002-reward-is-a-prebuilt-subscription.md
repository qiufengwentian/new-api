# 回馈以「按渠道类型发放的预建订阅」表达

回馈既不发钱包额度、也不按消耗分成，而是**管理端预建的订阅套餐**：管理端在清单条目上挂一个 `plan_id`，用户贡献成功即发放一个订阅实例（`model.AdminBindSubscription`），额度随订阅自身的每日重置规则清零。

## Considered Options

- **钱包额度**：本仓库没有任何额度过期机制（`model/user.go:97` 的 `Quota` 无过期字段，`model/` 里唯一的过期概念是兑换码的 `ExpiredTime`）。固定日额入钱包会永久累积——参照站的 $60/天 ≈ 每年 $21,900/用户——日额封顶随之失效。
- **消耗分成**：激励与站点收益同向、无法靠自充自耗套利，但用户难以预估收益，且与「每贡献一家 +$20/天」的拉新意图不符。
- **新增每日额度桶**：需要改扣费侧的取钱顺序（`service/funding_source.go`），实现量与复用订阅相当，而订阅这条路已有可用的发放、失效与每日重置三件现成机器。
